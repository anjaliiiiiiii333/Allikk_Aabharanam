## Architecture Diagram

```
User Interface (MainWindow.xaml)
    ↓
    ├─→ DesktopIconDetector
    │    └─→ Uses UIAutomation to find desktop items
    │        └─→ Calls Win32: FindWindow("Progman")
    │
    ├─→ KeychainTracker (Background Thread)
    │    ├─→ Continuously calls GetDesktopItemPosition()
    │    └─→ Updates overlay position every 100ms
    │
    └─→ KeychainOverlay (Separate Window)
         ├─→ WS_EX_LAYERED: Transparent, alpha-blended
         ├─→ WS_EX_TRANSPARENT: Click-through (mouse passes through)
         ├─→ Uses UpdateLayeredWindow() for efficient updates
         └─→ Displays Assets/keychain.png at relative position
```

## Key Technological Decisions

### Why UIAutomation for Desktop Detection?
- ✅ Works uniformly for files, folders, shortcuts (no special handling needed)
- ✅ Non-invasive (pure read-only access)
- ✅ Officially supported Windows API
- ✅ DPI-aware (BoundingRectangle already scaled)
- ✅ Multi-monitor capable (absolute screen coordinates)
- ✅ No file system access required
- ✅ No shell operations (safe, clean)

### Why Win32 Layered Windows for Overlay?
- ✅ Most efficient for transparent overlays
- ✅ Built-in alpha blending (32-bit RGBA support)
- ✅ Click-through capability (WS_EX_TRANSPARENT)
- ✅ UpdateLayeredWindow is fast (no redraw overhead)
- ✅ Native Windows API (reliable, well-documented)
- ✅ Works across Windows versions (XP to Windows 11)
- ✅ No performance impact on desktop

### Why WPF for UI?
- ✅ Modern, designed for Windows
- ✅ Easy XAML layout
- ✅ Good data binding and event handling
- ✅ Integrates well with Win32 interop
- ✅ Runs on .NET 8 (current LTS)

### Why Background Threading for Tracking?
- ✅ Prevents UI blocking
- ✅ Smooth tracking updates
- ✅ Clean cancellation model (CancellationToken)
- ✅ Easy event-based notifications (ItemLost, ItemFound)

## Usage Scenario: Step by Step

1. **User launches application**
   - MainWindow appears
   - AssetGenerator creates keychain.png if needed

2. **User clicks "Refresh Desktop Items"**
   - DesktopIconDetector.GetDesktopItems() runs
   - UIAutomation enumerates Progman window children
   - List populates with all detected items

3. **User selects "Document.txt"**
   - ListBox.SelectionChanged fires
   - "Attach Keychain" button becomes enabled

4. **User clicks "Attach Keychain"**
   - KeychainOverlay created (Win32 layered window)
   - KeychainTracker created (background thread started)
   - Overlay positioned at (itemX + itemWidth + 10, itemY + itemHeight + 10)
   - Tracking loop begins (100ms intervals)

5. **User drags "Document.txt" across desktop**
   - Tracking loop queries GetDesktopItemPosition()
   - UIAutomation returns new BoundingRectangle
   - KeychainOverlay.SetPosition() called
   - SetWindowPos() updates overlay position
   - Overlay appears to follow item

6. **User clicks "Detach Keychain"**
   - KeychainTracker.StopTracking() cancels background thread
   - KeychainOverlay.Dispose() destroys window
   - Resources cleaned up
   - UI returns to ready state

7. **User closes application**
   - Window_Closing event handler
   - Any active tracker/overlay stopped and disposed
   - Application exits cleanly
